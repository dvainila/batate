# Как расширять BMAD под свои задачи

В зависимости от задачи есть 3 уровня расширения — от самого лёгкого (без форка) до добавления собственных скиллов и модулей в этот репозиторий.

---

## Уровень 1. Кастомизация поведения без правки исходников

Если нужно адаптировать существующих агентов или workflow под стандарты твоей команды/проекта, **не нужно** править файлы в `src/`. Используй `_bmad/custom/` в целевом проекте (или запусти скилл `bmad-customize`).

Примеры, что можно сделать через `_bmad/custom/<skill-name>.toml`:

1. **Добавить проектные правила агенту или скиллу (`persistent_facts`):**
   ```toml
   [agent]
   persistent_facts = [
     "file:{project-root}/docs/architecture-rules.md",
     "Мы используем только PostgreSQL и FastAPI.",
   ]
   ```
   *(Массивы append-ятся к дефолтным из `customize.toml`.)*

2. **Добавить шаг при активации (`activation_steps_prepend` / `activation_steps_append`):**
   ```toml
   [agent]
   activation_steps_append = [
     "Прочитай {project-root}/docs/current-sprint-notes.md перед началом работы."
   ]
   ```

3. **Добавить или заменить пункт в меню агента (`[[agent.menu]]`):**
   ```toml
   [[agent.menu]]
   code = "MY"
   description = "Запустить мой кастомный чеклист"
   skill = "bmad-my-checklist"
   ```
   *(Если `code` совпадает с существующим, например `CR`, пункт заменится; если новый — добавится в конец.)*

4. **Поменять язык, пути артефактов или добавить своих агентов в команду:**
   Через `_bmad/custom/config.toml` (или `config.user.toml`).

## Уровень 2. Создание нового скилла или агента в этом форке

Если ты развиваешь свой форк этого репозитория и хочешь добавить новые скиллы/агенты, которые будут ставиться вместе с BMAD:

1. **Выбери место:**
   - Утилитарный скилл для любых проектов → `src/core-skills/bmad-<name>/`
   - Скилл разработки (планирование / поставка / агент) → `src/bmm-skills/plan|ship|agents/bmad-<name>/`
   - *(Опционально)* Свой отдельный модуль → отдельная папка модуля с `module.yaml` и `module-help.csv` (можно ставить как custom module через установщик).

2. **Создай структуру скилла:**
   - Обязательно: `SKILL.md` с frontmatter:
     ```yaml
     ---
     name: bmad-my-skill
     description: 'Что делает скилл. Use when пользователь просит ...'
     ---
     ```
   - Опционально: `customize.toml` с секцией `[workflow]` или `[agent]`, папки `references/`, `assets/`, `steps/`.
   - Если скилл должен появляться в подсказках `bmad-help`, добавь строку в `module-help.csv` соответствующего модуля.

3. **Соблюдай обязательные правила (`tools/skill-validator.md`):**
   - `name` в `SKILL.md` обязан начинаться с `bmad-` (lowercase, цифры, одиночные дефисы) и **точно совпадать** с именем папки.
   - В `description` должно быть указано не только *что* делает скилл, но и *когда* его использовать (`Use when ...` / `Use if ...`), до 1024 символов.
   - **Пути внутри скилла** — только относительные от текущего файла (`./references/guide.md`, `../template.md`). Запрещены `installed_path`, `{installed_path}`, абсолютные пути и хранение внутрискилловых путей в переменных.
   - **Внешние пути** — только через `{project-root}/...` или конфиг-переменные (`{planning_artifacts}/...`, `{project_knowledge}/...`).
   - **Запрещено лезть в файлы другого скилла по пути.** Если нужен другой скилл, пиши в тексте: ``Invoke the `other-skill` skill`` (слово `invoke`, а не `read` / `run` / `load`).
   - Если шаг выводит меню пользователю — обязательно явное указание **HALT** (остановиться и ждать ответа).
   - Установщик находит скиллы рекурсивно, поэтому вложенность внутри `plan/` или `ship/` на итоговый ID скилла не влияет.

## Уровень 3. Как проверять и тестировать свои изменения

1. **Валидация одного скилла (быстро):**
   ```bash
   uv run --python 3.11 tools/validate_skills.py --strict src/bmm-skills/plan/bmad-my-skill
   ```
   *(Проверяет 10 детерминированных правил из `tools/skill-validator.md`; оставшиеся 10 — семантические, их можно прогнать через LLM по тому же `tools/skill-validator.md`.)*

2. **Проверка ссылок и общих тестов репозитория:**
   ```bash
   npm run validate:skills
   npm run validate:refs
   npm run test:renderer
   ```
   Перед пушем (согласно `AGENTS.md`) — полный прогон:
   ```bash
   npm run quality
   ```

3. **Тестовая установка в реальный или песочный проект:**
   ```bash
   node tools/installer/bmad-cli.js install --directory /path/to/sandbox-project
   ```
   Установщик скопирует твои новые скиллы из `src/` в `.cursor/skills/` (или другую выбранную IDE) и развернёт `_bmad/` в песочнице.
